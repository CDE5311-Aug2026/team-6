## 主演示场景：Jessica 在上班，Mum 在家

1. 先由照顾者确认早餐的通常时间，例如 09:00–09:30；AI 的时间建议不能未经确认直接成为日程。
2. 10:00 Jessica 打开首页，看到 Feed Sunny breakfast，显示已超过计划时间，但尚无完成确认。
3. Jessica 点击 Remind caregiver，选择 Mum，再点击 Send reminder。文案要求先核实：若已经喂过，应记录完成情况，避免重复喂食。
4. Mum 打开 Pawsona，在首页看到站内提醒入口；进入 Plan & requests 可查看提醒来自谁、针对什么任务。
5. 若任务尚未指派，Mum 可以在首页点击 Mark done；若需要正式交接，沿用 Ask a caregiver → Accept／Can’t do it 的流程。
6. Mum 完成后标记，Jessica 看到 Done by Mum 和完成时间。验证时必须等待双方同步成功，不能只看到本机更新就宣称共享已生效。

临时照顾者使用同一流程，但必须是仍有效且可编辑的 care-circle 成员；Viewer 和已过期成员不能作为本轮提醒的目标。

## 状态与交互约定

- 时间提示表示“该核查计划”，不能推断“宠物没吃饭”或“照顾者失职”。确认时间窗内不会被标为超时。
- 提醒是 `reminded` 事件，保留 actor、target、时间和已读状态；不自动更改负责人或完成状态。
- 同一任务、同一接收者五分钟内限制重复提醒；不同任务、不同接收者分别计算。
- 发提醒后仍须查看同步状态。同步失败时沿用现有重试机制，不能声称对方已经收到或读到。
- 已完成和 Not today 的任务不能再次发提醒；完成后时间提示随状态关闭。
- 没有记录的宠物也能看到行动区；没有宠物时仍先引导 Add a pet。
- 首页行动区固定显示今天；Daily Rhythm 的历史浏览保留，不把历史任务混成今天待办。

## 验收步骤

| 检查 | 操作与预期 |
| --- | --- |
| 无 Story 的真实账户 | 建立宠物、确认早餐 Pattern；首页出现任务，不依赖模拟数据 |
| 时间提示 | 测试 08:44、08:45、09:00、09:30、10:00；分别为 Upcoming、15 分钟内、时间窗内、时间窗内、计划时间已过 |
| 早餐提醒 | 主要照顾者选择 Mum；Mum 的站内未读增加，历史中出现任务与发起人 |
| 去重 | 同项任务同接收者五分钟内不能重复发送；五分钟后可再次提醒 |
| 共享完成 | Mum 标记完成并等待保存成功；Jessica 刷新／等自动同步，看到 Mum 和同一时间 |
| 分工交接 | 确认 Pattern 任务能够 Ask a caregiver；对方接受后仍保留原有拒绝、退出与接手流程 |
| 权限 | Viewer 没有写操作；过期临时成员不能被选择提醒；不向其他照顾圈发送 |
| 模拟证据 | 模拟活动到点不会显示 Done by Mum；显示模拟活动且完成者未验证 |
| 保存冲突 | 两人同时操作时沿用版本检查；失败可见，不把本地提示当作成功送达 |
