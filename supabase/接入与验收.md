# Supabase 接入工作记录

状态：Pawsona（efihvahumvqyaumdqpcy，Singapore）已执行 personal_workspaces migration。前端已接入 Supabase Auth、private workspace 与 Storage，已部署并完成线上登录/读取验收。

## 首批接入范围

- 保留 Guest → Luna，本地访客数据不自动上传。
- 正式账号使用用户名和密码，通过 Supabase Auth 验证身份。
- 用户自己的 profile 与 workspace 云端保存；workspace 首阶段保留原型的数据结构。
- 每条 workspace 只属于一个 auth.uid()，RLS 在数据库端隔离用户。
- 第二台设备写入前使用 revision 检查；冲突时提示重新加载，不能静默覆盖。
- 图片和音频进入私有 Storage，数据只保存稳定路径；signed URL 不作为永久地址保存。

照护圈真实多人共享需要下一批关系表与成员权限，当前本地邀请不能直接当作云端授权。正式云端模式已禁用本地账号切换、模拟邀请、主照护者转移及本地账号删除入口。

## 连接后执行

1. 确认目标 Supabase 项目及 Free 套餐。
2. 读取现有 schema，确认同名表不存在，再执行 migration；不覆盖已有项目表。
3. 配置 Auth 的 Site URL 与 redirect allowlist：
   https://pawsona-team6-preview.vercel.app/
4. 用户名注册通过 register-username Edge Function，不使用 SMTP。
5. 使用官方 SDK，公开配置只包含项目 URL 与 publishable key。secret/service_role 不得进入 VITE_*、仓库或浏览器。
6. 将云端读写与 App 状态连接，首次加载完成前禁止写入空数据。
7. 本地数据迁移单独询问用户并预览内容；不能将同一浏览器所有模拟账号上传到一个真实账号。
8. 本地验证后建立 PR，通过真实项目验收，再更新 Vercel。

## 验收

- Guest 无需登录，仍进入 Luna；Guest 不写入 Supabase。
- 未验证身份不能读取或写入 workspace。
- 两个测试用户互相不能读取、修改或删除数据和附件。
- 同一真实用户在两个浏览器读取相同宠物及观察记录。
- 网络失败显示未同步；重试与设备冲突不会静默丢失资料。
- 登出不清除 Guest 数据，且之后不能继续访问云端数据。
- 私有附件不依赖上一次会话生成的短期 URL。
- 用户名注册、重复用户名、密码登录在实际线上域名验证。

## 尚需配置及边界

- 当前用户名流程不收集或验证真实邮箱，不发送注册邮件。
- 不关闭邮箱验证来绕过邮件限制。
- 首阶段每用户 workspace 以 JSONB 保存（1 MB 上限，不含已上传媒体），不等于多人共享关系模型。
- 附件单个上限 10 MB；视频格式尚未开放，支持的图片/音频格式见 migration。
- 断网时编辑仅保留在当前页面内存；刷新/关闭前会警告。可重试或下载记录备份。
- 删除记录不会自动回收孤立附件，后续应加引用追踪清理。
- 尚不提供访客资料导入、找回密码或正式账户删除。

## 用户名注册更新（2026-10-15）

- 注册与登录只显示 Username、Password；用户名大小写不敏感，3–24 位字母/数字/下划线。
- Edge Function 仅可创建 users.pawsona.invalid 保留域下的内部 Auth 标识，不接受真实邮箱或任意角色。
- 管理员凭据仅存在 Supabase 服务器环境，不返回给客户端。
- pre-login 注册端点使用 publishable API key 验证、精确 CORS 来源、输入验证和数据库配额；不是需要现有用户 JWT 的接口。
- 配额表位于不暴露的 pawsona_private schema；RLS 无客户端 policy 为刻意的默认拒绝，只有 service_role 可访问。
- 没有关闭项目全局邮箱验证设置。用户名身份不代表任何真实邮箱的所有权。
- 注册无需 SMTP；目前不提供找回密码。
- 6 项单元测试与真实注册/登录/重复检查/独立会话数据读取通过。
